## S1

- Stakeholder: Student attendee
- Stakeholder type: end user
- Power-interest quadrant: keep informed
- Main goal: Easily find and follow campus events and announcements in one place.
- Main concern: RSVP privacy and accessibility for students using phones or screen readers.
- How you would involve or monitor this stakeholder: Collect student feedback and run usability and accessibility testing with students.

## S2

- Stakeholder: Group officer
- Stakeholder type: end user
- Power-interest quadrant: key player
- Main goal: Create and manage group announcements and events collaboratively.
- Main concern: Only approved officers should be able to publish, and attendees should be notified when event details change.
- How you would involve or monitor this stakeholder: Involve group officers in testing publishing permissions, event visibility, and event update notifications.

## S3

- Stakeholder: Campus moderator
- Stakeholder type: operations
- Power-interest quadrant: key player
- Main goal: Review reports and moderate inappropriate or harmful campus content.
- Main concern: Moderators must be able to hide events quickly while preserving evidence and a record of moderation decisions.
- How you would involve or monitor this stakeholder: Involve moderators in testing reporting, hiding content, evidence retention, and the appeals process.

## S4

- Stakeholder: Student Affairs
- Stakeholder type: business
- Power-interest quadrant: key player
- Main goal: Provide a trusted campus service for verified groups before Orientation Week.
- Main concern: Official badges must only be given to verified groups, and the pilot must support 5,000 students and 200 groups.
- How you would involve or monitor this stakeholder: Involve Student Affairs in verification policy decisions, release planning, and pilot readiness reviews.

## S5

- Stakeholder: Data Protection Officer
- Stakeholder type: regulator
- Power-interest quadrant: keep satisfied
- Main goal: Ensure that CampusPulse protects personal data and follows privacy requirements.
- Main concern: The service should collect only necessary personal data, keep RSVP lists private by default, and delete attendance data within 30 days after an event is cancelled.
- How you would involve or monitor this stakeholder: Consult the Data Protection Officer on privacy requirements and review data collection, RSVP visibility, and data retention policies.

## S6

- Stakeholder: Malicious or compromised users
- Stakeholder type: negative stakeholder
- Power-interest quadrant: minimal effort
- Main goal: Misuse CampusPulse by impersonating verified groups or repeatedly posting harmful content.
- Main concern: Phishing events, group impersonation, and repeated spam announcements could harm users and reduce trust in the service.
- How you would involve or monitor this stakeholder: Monitor reports and suspicious activity, and test the system against impersonation and repeated-post abuse cases.

## Conflicts to resolve

Describe at least two real tensions. For each one, name both stakeholder IDs
and either propose a decision or write a specific question that should go back
to the stakeholders.

### Conflict 1

- Stakeholders: S1 and S2
- What conflicts: Group officers may want to know who has RSVP'd to manage attendance, while students want their RSVP identity to remain private unless they choose to make it visible.
- Proposed decision or follow-up question: Keep RSVP identities private by default and allow students to choose whether their identity is visible.

### Conflict 2

- Stakeholders: S3 and S5
- What conflicts: Campus moderators need to preserve evidence for appeals, while the Data Protection Officer requires personal and attendance data to be retained only as long as necessary.
- Proposed decision or follow-up question: What moderation evidence must be retained for an appeal, and how long may that evidence be stored before it must be deleted?
